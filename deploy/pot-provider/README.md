# Optional anonymous PO Token sidecar (review only, disabled by default)

The backend never starts this service. Existing production rollout files and configuration are not changed. Setting `MUSE_YOUTUBE_POT_SOCKET=/run/muse-pot/provider.sock` opts a POSIX Python backend into the broker on a future explicitly authorized deployment; every other value is disabled. This setting is read only in the parent, not accepted from API clients or forwarded to worker children. No service is started merely by checking capability.

## Boundaries

The backend supplies a socketpair FD to its admitted YouTube worker. A per-job broker checks the original video's ID, `mweb` client, `gvs` context and either guest visitor binding or experimental video binding. No arbitrary URLs, headers, challenge programs, proxy, cookies, source addresses or TLS overrides can cross IPC. This channel bypasses neither the worker's public-address socket guard nor its Deno sandbox: the worker never connects to the sidecar socket.

The parent connects only to `/run/muse-pot/provider.sock`, requiring a real socket (no symlink), owner UID matching the API, mode 0600 and a peer with the same UID. The sidecar independently checks the peer UID. Deploy the API and sidecar under the same dedicated **non-root** UID; the current production's runtime identity must be reviewed before enabling. Do not change ownership/permissions on existing production data merely to enable this feature. The shared volume holds only this socket, not data, profiles, keys or token files. Both ends are trusted under that deployment UID; Unix permissions do not isolate mutually untrusted processes with the same UID.

Each job can trigger at most one mint attempt. Repeated identical requests reuse the job's in-memory response until the smaller of its validated expiry and 480 seconds; a changed binding/context or expiry fails without retry. Failure/timeout also consumes the attempt. No tokens, visitor data or provider errors are written to job JSON, returned in HTTP API, printed or stored in scratch. Python/JS immutable strings cannot be guaranteed cryptographically zeroed; references are dropped at job closure and the worker exits. Cancel/revocation/worker completion shuts down the provider connection. The sidecar detects disconnect and kills only that mint child's process group. CPU/wall/stdout/process count are bounded; there are at most two connections/mint subprocesses.

The sidecar invokes a separate Node process for each request. The wrapper imports the pinned upstream SessionManager without starting upstream's HTTP server, forces one HTTP attempt rather than the upstream retry loop, bypasses caches and exits after the result. Any minter/guest/token cache disappears with that process. Stdout/stderr from the upstream library are suppressed before import; only the bounded validated response is emitted over the private pipe. No warm-up, token prefetch, background refresh, browser cookie import, logged-in Google account, public HTTP port, external yt-dlp plugin or automatic client rotation is enabled. Fresh anonymous upstream requests can still receive transient guest cookies/identifiers from YouTube; they are not browser cookies or persisted profiles.

The sidecar executes reviewed third-party code and BotGuard JS with outbound network access when enabled. **It does not inherit the worker's Python socket guard or EJS deny-network sandbox.** Before any live enablement, isolate its egress from loopback/host, metadata, private/link-local networks and other tenants using a separately reviewed container/network firewall. Retain DNS access to a controlled resolver and public HTTPS for the attestation services. Same controlled public egress as the media worker is preferable; successful PO Token generation does not guarantee IP-based login restrictions are removed. No proxy/IP rotation fallback is provided. This PR does not alter host firewall or production network policy.

## Reproducible packaging

Build context is repository root; `deploy/pot-provider/Dockerfile` fetches the exact upstream archive with SHA-256 validation, builds from package-lock and retains its full source/license in `/opt/bgutil`. Node base image is digest pinned. Upstream bgutil provider 2.0.2: commit `26475e9d3665b972c4aeb83b4dbaafcf64b88438`, GPL-3.0-only. Source and license remain separate from Muse's custom IPC wrapper; review redistribution/license obligations before publishing the image. No upstream source is copied into the Muse repository.

The image is non-root. A later deployment must provide only a private writable socket directory, read-only root filesystem, bounded /tmp tmpfs, cap-drop ALL, no-new-privileges, memory/CPU/PID limits, no Docker socket, no production env or profile mounts and no published port. Do not run the default entrypoint in a network-enabled container as a packaging test: an actual token request would contact YouTube.

## Offline verification (no attestation or download)

- `python tests/run_backend_offline.py tests/test_pot_broker.py`: synthetic tokens, blocked external IO, cache and scope isolation, cancellation/revocation, strict frames and fixed safe failures, actual yt-dlp extractor adapter.
- `node tests/pot_mint_contract.mjs`: wrapper evaluated in a VM with a mocked upstream module/process/fs; verifies bypass-cache input, single HTTP attempt, raw-log suppression and oversize/failure behavior. Does not execute upstream generator.
- Image check: override entrypoint to `python3 /opt/muse/check_offline.py` in a network-none read-only container with /tmp tmpfs. The check replaces `mint` before requests, forbids subprocess generation, and exercises real Unix IPC/UID permissions.
- `node /opt/muse/mint_contract.mjs` in that network-none image checks wrapper with mocks. Separately importing SessionManager and inspecting its prototype proves packaged dependency compatibility without constructing a manager or minting a token.

CI builds this optional image and performs only those offline entrypoint overrides. It never starts the real sidecar server or activates the backend setting. Backend image build/startup/auth/persistence checks remain separate. No live proof of token minting, expiry behavior from Google, provider throughput or successful downloads is claimed.
